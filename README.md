# FOXPRO — контрольный прогон на изолированном ПК

## Цель

Этот репозиторий содержит исходные FoxPro-модули, данные и подготовленную инфраструктуру для **контрольного прогона** исходной логики с `NKO803.DAT` / `NORMMATO`.

На изолированном ПК вся рабочая среда должна находиться только на `C:`. Корпоративная сеть должна быть отключена.

## Что требуется после клонирования

После `git clone` нужно выполнить только два действия:

1. Запустить двойным щелчком:

       tools\setup_control.bat

2. После успешного завершения запустить:

       tools\START_CONTROL_RUN.bat

Visual FoxPro IDE на изолированном ПК **не требуется**, если используется уже скомпилированная `ADMINSTR\administ.exe` / `ADMINSTR.EXE` из репозитория.

---

# 1. Важное требование: Git LFS

Каталог `NORMATIV` содержит большие бинарные DBF/CDX-файлы и хранится через Git LFS. В репозитории это явно указано в `.gitattributes` для `NORMATIV/**`. Поэтому на компьютере, с которого выполняется clone, должен быть установлен Git LFS и должны быть загружены LFS-объекты. fileciteturn65file0L2-L10

После clone, если Git LFS не скачал файлы автоматически, выполнить:

    git lfs install
    git lfs pull

Проверить, что `NORMATIV\NORMMATO.DBF` является настоящим бинарным DBF, а не маленьким текстовым LFS-pointer-файлом. Исходный LFS-объект `NORMMATO.DBF` имеет размер около 8.2 MB. fileciteturn61file0L2-L10

`setup_control.bat` сам остановится с понятной ошибкой, если обнаружит LFS-pointer вместо реального файла.

---

# 2. Что делает setup_control.bat

`tools\setup_control.bat` запускает `tools\setup_control.ps1`; исходная версия BAT уже определяет корень репозитория относительно собственного каталога, поэтому его можно запускать двойным щелчком. fileciteturn69file0L2-L10

Обновлённый setup:

1. Проверяет наличие `PDO`, `ADMINSTR`, `dat`, `Cex\PUTI.DBF`, `NORMATIV`.
2. Проверяет, что LFS-файлы `NORMMATO.DBF/CDX` действительно скачаны.
3. Создаёт рабочие каталоги на `C:`.
4. Очищает предыдущие рабочие копии, чтобы предыдущий прогон не загрязнил контрольный.
5. Копирует `PDO` → `C:\PDO`.
6. Копирует `ADMINSTR` → `C:\FOXPRO_CONTROL\ADMINSTR`.
7. Копирует `dat` → `C:\FOXPRO_CONTROL\DAT`.
8. Копирует **весь `NORMATIV` из репозитория** → `C:\NORMATIV`.
9. Копирует `Cex\PUTI.DBF/CDX` → `C:\CEX`.
10. Сохраняет оригинальную локальную PUTI в `C:\FOXPRO_CONTROL\PUTI_BEFORE_CONTROL`.
11. Настраивает запись АРМ 20 в локальной `PUTI.DBF`.
12. Копирует исходные PRG в `C:\FOXPRO_CONTROL\SOURCE_PRG` для аудита.

---

# 3. Пути

Для АРМ 20 используются:

    ad_start = C:\PDO\CEX\
    ad_norm  = C:\NORMATIV\
    ad_normS = C:\FOXPRO_CONTROL\NET_MIRROR\
    ad_vig   = C:\FOXPRO_CONTROL\DAT\
    ad_netR  = C:\FOXPRO_CONTROL\NET_RESTRICTED\

`puti_.prg` использует `C:\CEX\PUTI.DBF` и по `id_ar` получает значения адресов из PUTI. fileciteturn57file0L2-L2

Поэтому для этих путей не нужно вручную менять десятки PRG.

---

# 4. Что такое C:\NORMATIV

`C:\NORMATIV` — рабочая копия каталога `NORMATIV` из репозитория.

Она **не должна содержать результаты предыдущего контрольного прогона**.

При каждом запуске `setup_control.bat` рабочая копия очищается и заново копируется из репозитория. Это позволяет начинать контрольный прогон из одинакового состояния.

После запуска программы DBF/CDX в `C:\NORMATIV` могут изменяться, создаваться, очищаться или перезаписываться — это зависит от конкретного PRG. Например, `_norma.prg` очищает существующий `NORMMATO` и заново заполняет его данными. Поэтому наличие `NORMMATO.DBF` в исходной папке само по себе не означает, что старые данные будут сохранены. 

---

# 5. NKO803 → NORMMATO

Для контрольного прогона `NKO803.DAT` остаётся исходным.

Ожидаемая цепочка:

    C:\FOXPRO_CONTROL\DAT\NKO803.DAT
                     ↓
                 _norma.prg
                     ↓
          C:\NORMATIV\NORMMATO.DBF
                     ↓
          последующие модули

Не очищай и не подменяй `NKO803.DAT` перед контрольным прогоном.

---

# 6. Запуск программы

После успешного setup запустить:

    tools\START_CONTROL_RUN.bat

Он запускает:

    C:\FOXPRO_CONTROL\ADMINSTR\administ.exe

или, если первого файла нет:

    C:\FOXPRO_CONTROL\ADMINSTR\ADMINSTR.EXE

Перед запуском убедись, что компьютер отключён от корпоративной сети. BAT специально предупреждает не запускать `C:\PDO\N_NSI.bat`, поскольку этот BAT предназначен для обновления с сетевого сервера. 

---

# 7. Как выполнять контрольный прогон

Не нужно вручную запускать все `.PRG` подряд.

После старта используй штатный интерфейс администратора и выполняй обычную последовательность формирования выгрузок.

Исходные PRG в контрольном прогоне не изменяются.

---

# 8. Где будут результаты

Во время работы результаты находятся непосредственно в:

    C:\NORMATIV\

Также программы могут формировать локальные копии в:

    C:\FOXPRO_CONTROL\NET_MIRROR\

и другие локальные рабочие каталоги, если это предусмотрено текущей логикой.

После завершения прогона **не запускай тестовую версию поверх этих же данных**.

---

# 9. Сохранение контрольного результата

После завершения контрольного прогона запусти:

    tools\SNAPSHOT_CONTROL.bat

Скрипт создаёт каталог:

    C:\FOXPRO_CONTROL\RUNS\CONTROL_YYYYMMDD_HHMMSS\

и сохраняет туда:

    NORMATIV\
    DAT\
    CEX\
    PDO_CEX\
    ADMINSTR\
    SHA256SUMS.txt

Таким образом исходный результат контрольного прогона сохраняется отдельно.

---

# 10. Python не требуется

`patch_puti.py` больше не используется в процессе setup.

Настройка `PUTI.DBF` теперь выполняется непосредственно в `setup_control.ps1`.

Поэтому на изолированном ПК **Python устанавливать не нужно**.

Файл `tools\patch_puti.py` оставлен только как исторический/вспомогательный файл и не является частью запуска.

---

# 11. Visual FoxPro

Visual FoxPro IDE не нужен для запуска существующей скомпилированной программы.

Он понадобится только в том случае, если в будущем потребуется изменить PRG и затем пересобрать новую EXE.

---

# 12. Тестовая версия без оборотной стороны

Контрольную среду сначала полностью сохранить через `SNAPSHOT_CONTROL.bat`.

Только после этого создаётся отдельная TEST-среда.

Контрольную и тестовую среды нельзя смешивать, иначе результаты будет невозможно корректно связать с изменением `NORMMATO`.
