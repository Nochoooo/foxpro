# FOXPRO — контрольный прогон на изолированном ПК

## Что должно получиться

После клонирования репозитория задача подготовки должна сводиться к двум действиям:

1. На изолированном ПК открыть `tools\setup_control.bat`.
2. После его завершения открыть `START_CONTROL_RUN.bat`.

Visual FoxPro IDE на изолированном ПК для запуска уже скомпилированной программы не требуется.

---

# 1. До переноса на изолированный ПК

Клонируй репозиторий:

    https://github.com/Nochoooo/foxpro

Например:

    C:\foxpro

В этой папке должны находиться `ADMINSTR`, `Cex`, `PDO`, `dat` и исходные `PRG`.

Для контрольного прогона не меняй исходные PRG.

---

# 2. Что делает `setup_control.bat`

Скрипт автоматически:

1. Создаёт локальные каталоги:

   C:\CEX
   C:\NORMATIV
   C:\NORMATIV\OPER
   C:\NORMATIV\TEMP
   C:\PDO
   C:\FOXPRO_CONTROL\ADMINSTR
   C:\FOXPRO_CONTROL\DAT
   C:\FOXPRO_CONTROL\NET_MIRROR
   C:\FOXPRO_CONTROL\NET_RESTRICTED
   C:\FOXPRO_CONTROL\RUNS

2. Копирует `PDO` из репозитория в `C:\PDO`.
3. Копирует `ADMINSTR` в `C:\FOXPRO_CONTROL\ADMINSTR`.
4. Копирует каталог `dat` в `C:\FOXPRO_CONTROL\DAT`.
5. Копирует `Cex\PUTI.DBF/CDX` в `C:\CEX`.
6. Делает резервную копию исходной локальной PUTI.
7. Автоматически изменяет запись АРМ 20 в `C:\CEX\PUTI.DBF`, чтобы пути были только на C:.

Настраиваются:

    ad_start = C:\PDO\CEX\
    ad_norm  = C:\NORMATIV\
    ad_normS = C:\FOXPRO_CONTROL\NET_MIRROR\
    ad_vig   = C:\FOXPRO_CONTROL\DAT\
    ad_netR  = C:\FOXPRO_CONTROL\NET_RESTRICTED\

Исходный `Cex\PUTI.DBF` в репозитории не изменяется.

---

# 3. Почему PUTI меняется автоматически

`puti_.prg` открывает:

    C:\CEX\PUTI.DBF

и по `id_ar=20` получает адреса `ad_start`, `ad_norm`, `ad_normS`, `ad_vig`, `ad_netR`.

Поэтому изменять десятки PRG только ради этих путей не требуется.

# 6. Что делать после setup

Запусти:

    C:\foxpro\START_CONTROL_RUN.bat

(или `START_CONTROL_RUN.bat` в корне клона).

Он запускает имеющуюся в репозитории скомпилированную программу `administ.exe`; если её нет — пробует `ADMINSTR.EXE`.

---

# 7. Сеть

Изолированный ПК должен оставаться отключённым от корпоративной сети.

НЕ запускай:

    C:\PDO\N_NSI.bat

Этот BAT содержит сетевой путь к `\\nwnt\...` и предназначен для обновления приложения с сервера.

---

# 9. Что делать, если на старте программа требует TAB_SQL

`dostyp_d.prg` может использовать:

    C:\NORMATIV\TAB_SQL.DBF

Если рабочая конфигурация администратора использовала эту таблицу, её локальную копию нужно положить в `C:\NORMATIV`.

Не придумывай её содержимое. Используй копию из исходного рабочего окружения.

---

# 10. Контрольный снимок

После завершения прогона запусти:

    SNAPSHOT_CONTROL.bat

Результат будет сохранён в:

    C:\FOXPRO_CONTROL\RUNS\<дата_время>\

Там будут копии результатов, DAT, CEX, PDO\CEX, ADMINSTR и SHA-256 контрольные суммы.

Не запускай тестовую версию поверх этого же каталога.

---

# 11. Возврат PUTI

`restore_puti.prg` больше не требуется для обычного запуска на изолированном ПК: исходная PUTI остаётся в репозитории, а локальная резервная копия хранится в:

    C:\FOXPRO_CONTROL\PUTI_BEFORE_CONTROL\

---

# 12. Важное ограничение

Этот комплект автоматизирует именно подготовку локальной среды и запуск существующей скомпилированной контрольной версии.

Если после изменения исходных PRG потребуется новая EXE, компиляция выполняется отдельно на компьютере с Visual FoxPro.

На изолированном ПК Visual FoxPro IDE устанавливать для запуска существующей EXE не требуется.
